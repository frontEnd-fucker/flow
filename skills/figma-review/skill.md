## 概述
使用figma截图和实现页面进行1:1的视觉对比，并自动修复发现的视觉对齐问题

## 执行流程

**当用户直接提供对比页面和figma链接时直接跳到第三步**

**严格按照 skill 流程的每一步执行，不要跳过任何步骤，完成一步确认后再进行下一步**

### 第一步：**自动提取 Figma 链接**：
  - 扫描项目中的页面文件（如 `pages/**/*.tsx`, `app/**/*.tsx`, `src/pages/**/*.vue` 等）
  - 从文件头部注释中提取 Figma URL（格式：`https://figma.com/design/:fileKey/:fileName?node-id=1-2`）
  - 注释格式示例：
    ```typescript
    /**
    * Figma: https://figma.com/design/AbCdEf123/ProjectName?node-id=1-2
    * 或
    * @figma https://figma.com/design/AbCdEf123/ProjectName?node-id=1-2
    */
    ```

  - **如果没有找到 Figma 链接**：
   - 尝试从 `docs/requirements.md` 中提取
   - 如果仍未找到，询问用户提供 Figma 文件 URL

### 第二步：页面发现流程

**自动发现可比对的页面：**

1. 扫描项目结构，识别所有页面文件
2. 提取每个页面文件头部的 Figma 链接
3. 生成页面列表供用户选择，列表需要包含用户手动提交要review的页面和对应的figma节点的选项：

```json
{
  "questions": [
    {
      "question": "请选择要进行比对的页面",
      "header": "页面选择",
      "multiSelect": true,
      "options": [
        {"label": "登录页 - pages/login.tsx"},
        {"label": "首页 - pages/index.tsx"},
        {"label": "用户管理 - pages/users.tsx"}
        {"label": "手动提交要review的页面和对应的figma节点"}
      ]
    }
  ]
}
```

**options 限制**：每个 question 的 options 最多 4 个，超过时需要拆分多个 question。

### 第三步： 获取figma截图

**对每个选中的页面执行以下步骤：**

**约束：截图应该在整个流程中可用，后续流程不要再对同一个figma节点截图**

使用 `get_screenshot` 工具传入正确参数获取 Figma 设计稿截图，传入以下参数：

```json
{
  “fileKey”: “从URL提取的fileKey”,
  “nodeId”: “从URL提取的nodeId（-替换为:）”
}
```

### 第四步：获取实现页面的截图

找到正确的开发服务器端口，如果没有则启动一个，使用 `chrome-devtools-mcp` 的 `take_screenshot` 工具传入正确参数获取实现页面的截图并保存到`/screenshot`文件夹下

**参数说明：**
- `filePath`: 截图保存路径，格式为 `/screenshot/{页面名称}.png`
- `fullPage`: 是否截取全页，设置为 `true`
- 确保页面已加载完成后再截图

**工具调用示例：**
```json
{
  "filePath": "/screenshot/login.png",
  "fullPage": true
}
```

**执行步骤：**
1. 使用 `navigate_page` 导航到本地开发服务器页面（如 `http://localhost:3000/login`）
2. 等待页面完全加载
3. 使用 `take_screenshot` 截取页面截图并保存到 `/screenshot` 目录

完成后宣告用户：“文件已经保存到/screenshot文件夹”

### 第五步： 视觉对比环节一：Figma 截图 vs 实现页面截图

**非常严格**地从以下维度对figma截图和实现页面的截图进行1:1对比，不要放过任何细小的差异，输出详细的差异报告：

| 检查项 | 说明 |
|-------|------|
| **布局** | 元素位置、间距、对齐方式等是否符合设计稿 |
| **组件** | 各个组件的位置以及组件间的间距是否与figma一致|
| **颜色** | 背景色、文字色、按钮色等是否与 Figma 一致 |
| **字体** | 字体族、字号、字重、行高等是否匹配 |
| **尺寸** | 元素宽高、内边距、外边距等是否准确 |
| **图标** | 图标是否一致，仔细检查图标形状是否一致，而不是只从图标的命名去判读 |

##### 1:1视觉对比原则
- 逐个像素地比对每个 UI 元素
- 不放过任何细小差异

### 第六步： 视觉对比环节二：Figma 截图 vs 实现页面（实时检视）

在完成截图对比后，**直接在浏览器中打开实现页面**，结合 Figma 设计稿进行实时检视对比。这个环节与截图对比使用相同的维度和原则，但添加了以下检查项：

| 检查项 | 说明 |
|-------|------|
| **交互状态** | 悬停、点击、聚焦等状态下的视觉表现 |
| **动态效果** | 动画、过渡、加载状态等 |

**执行步骤：**
1. 保持 Figma 设计稿截图可见作为参考
2. 在浏览器中导航到实现页面
3. 逐一检查上述维度，记录发现的差异
4. 测试各种交互状态（悬停、点击等）

### 第七步：向用户展示差异报告
向用户展示如下完整的差异报告：

输出格式：
```markdown
### 【页面名称】完整差异报告

---

## 环节一：Figma 截图 vs 实现页面截图

**Figma 设计稿：**
[截图路径]

**实现页面：**
[截图路径]

**截图对比差异检查：**

| 检查项 | 状态 | 说明 |
|-------|------|------|
| 布局 | ✅ 通过 | 左右间距与设计稿一致 |
| 颜色 | ⚠️ 警告 | 按钮主色使用 `#1890ff`，设计稿为 `#1677ff` |
| 字体 | ❌ 不符 | 标题字号 18px，设计稿为 16px |
| ... | ... | ... |

---

## 环节二：Figma 截图 vs 实现页面（实时检视）

**检查方式：** 浏览器实时检视 + Figma 设计稿参考

**实时检视差异检查：**

| 检查项 | 状态 | 说明 |
|-------|------|------|
| 布局 | ✅ 通过 | 元素位置与设计稿一致 |
| 颜色 | ✅ 通过 | 颜色匹配准确 |
| 字体 | ❌ 不符 | 行高略大于设计稿 |
| 交互状态 | ⚠️ 警告 | 按钮悬停效果颜色偏浅 |
| 动态效果 | ✅ 通过 | 动画过渡流畅 |
| ... | ... | ... |

---

## 综合差异汇总

**列出所有发现的不通过的检查，不要省略任何警告或不符的条目（按优先级排序）：**

| 优先级 | 检查项 | 来源环节 | 说明 |
|-------|-------|---------|------|
| 🔴 高 | 字体 | 截图对比 | 标题字号 18px，设计稿为 16px |
| 🔴 高 | 字体 | 实时检视 | 行高略大于设计稿 |
| 🟡 中 | 颜色 | 截图对比 | 按钮主色使用 `#1890ff`，设计稿为 `#1677ff` |
| 🟡 中 | 交互状态 | 实时检视 | 按钮悬停效果颜色偏浅 |

**修复建议（按优先级）：**
1. 🔴 将标题字号从 18px 改为 16px
2. 🔴 调整行高以匹配设计稿
3. 🟡 将按钮主色从 `#1890ff` 改为 `#1677ff`
4. 🟡 调整按钮悬停效果的颜色
```

### 第八步： 自动修复循环流程，此步骤不能跳过且无需向用户确认

如果发现差异，**无需再询问用户**，启动自动修复循环（最多 5 次）：

#### 循环流程

```
第 1 次比对 → 发现差异 → 自动修复 → 第 2 次比对
     ↓
第 2 次比对 → 发现差异 → 自动修复 → 第 3 次比对
     ↓
第 3 次比对 → 发现差异 → 自动修复 → 第 4 次比对
     ↓
第 4 次比对 → 发现差异 → 自动修复 → 第 5 次比对
     ↓
第 5 次比对 → 仍有差异 → 终止循环 → 生成最终报告交用户决策
```

#### 每次修复后重新比对

**修复步骤：**
1. 根据综合差异汇总生成修复方案（按优先级排序）
2. 修改对应的代码文件
3. 保存后重新刷新页面
4. **重新执行完整的双环节对比流程：**
   - 重新获取 Figma 设计截图（缓存）
   - 重新获取实现页面截图（刷新后）
   - 重新进行环节一：截图对比检查
   - 重新进行环节二：实时检视检查
   - 生成新的完整差异报告

#### 循环终止条件

- ✅ **无差异**：对比结果通过，所有检查项为 ✅，终止循环
- ⚠️ **达上限**：已完成 5 次修复循环，仍有差异，终止循环
- 🛑 **手动中断**：用户要求停止自动修复

#### 第九步：最终报告
**确保修改前和修改后的截图都保存到/screenshot目录**

**情况 1：修复成功（无差异）**
```markdown
## 修复完成报告

**页面：** {页面名称}
**修复轮次：** 3 次
**最终状态：** ✅ 所有检查项通过（双环节对比）

**对比环节覆盖：**
- ✅ 环节一：Figma 截图 vs 实现页面截图
- ✅ 环节二：Figma 截图 vs 实现页面（实时检视）

**修复历史：**
- 第 1 轮：修复按钮颜色、调整标题字号
- 第 2 轮：修复间距、调整图标大小、修复悬停状态
- 第 3 轮：微调布局对齐、优化动画过渡 → 双环节均通过
```

**情况 2：达到循环上限（需用户决策）**
```markdown
## 修复报告 - 需用户决策

**页面：** {页面名称}
**修复轮次：** 5 次（已达上限）
**最终状态：** ⚠️ 仍有差异

**对比环节状态：**
- 环节一：Figma 截图 vs 实现页面截图 - ⚠️ 部分通过
- 环节二：Figma 截图 vs 实现页面（实时检视） - ⚠️ 部分通过

**剩余问题清单（按环节分类）：**

### 环节一剩余问题：
| 检查项 | 状态 | 说明 |
|-------|------|------|
| 颜色 | ⚠️ 警告 | 渐变背景色无法精确匹配 |
| 字体 | ⚠️ 警告 | 特殊字体需要授权 |

### 环节二剩余问题：
| 检查项 | 状态 | 说明 |
|-------|------|------|
| 交互状态 | ⚠️ 警告 | 输入框聚焦动画与设计稿有差异 |

### 综合优先级排序：
| 优先级 | 检查项 | 来源环节 | 说明 |
|-------|-------|---------|------|
| 🟡 中 | 颜色 | 环节一 | 渐变背景色无法精确匹配 |
| 🟡 中 | 交互状态 | 环节二 | 输入框聚焦动画与设计稿有差异 |

2. 继续手动修复（可能较复杂）
3. 调整设计稿以匹配实现

请选择下一步操作：
```

### 完成后

1. 汇总所有页面的对比结果和修复历史
2. 生成最终报告（修复成功/需用户决策）
3. 如有未解决问题，清晰列出供用户决策
