# Figma 样式同步

根据用户提供的组件名到 Figma node 的映射表，获取 Figma 设计稿中的样式，并自动修改代码中对应组件的样式。

## 流程

1. **获取初始映射表**
   - 询问用户提供组件名到 Figma node 的映射表
   - 格式示例：
     ```
     Button: https://figma.com/design/xxx/xxx?node-id=1-2
     Card: https://figma.com/design/xxx/xxx?node-id=3-4
     ```
   - 或接受简化的 `组件名: nodeId` 格式

2. **检测并处理父子组件关系**
   **此步骤在获取初始映射后立即执行**

   - 对于映射表中的每个组件：
     a. 读取组件代码文件，识别所有 import 的子组件
     b. **如果发现子组件**，必须询问用户：
        > "检测到 [组件名] 包含以下子组件：[子组件列表]。请提供它们对应的 Figma node 映射，或选择：
        > 1. 提供子组件独立的 Figma URL
        > 2. 指定父组件 Figma 中的子节点（格式：`CardItem: node-id=5-6`）
        > 3. 让 agent 尝试自动从父组件设计稿中提取对应部分", agent将调用 `get_metadata` 获取该节点 Figma 节点树信息查找到对应子组件的figma节点，然后通过`get_design_context`获取子组件设计信息
     c. 根据用户选择，将子组件添加到映射表中

3. **获取所有组件的 Figma 设计信息**
   - 对于完整映射表（包括父组件和子组件）中的每个组件：
     a. 调用 Figma MCP 的 `get_design_context` 工具获取设计信息
     b. 如果是子组件且使用父组件的子节点，使用对应的 nodeId 调用
     c. 将所有设计信息保存到[design_context]

4. **查找组件文件**
   **重要：此步骤必须直接执行，无需询问用户确认**

   - 在项目中搜索与组件名匹配的文件
   - 常见命名模式：
     - `Button.tsx` / `button.tsx`
     - `Button/index.tsx`
     - `components/Button.tsx`
   - **匹配策略**：
     - 如果找到唯一匹配 → **直接匹配**
     - 如果找到多个匹配 → 选择最匹配的一个（通常是与组件名完全相同的文件）**然后直接修改**
     - 如果找不到匹配 → 询问用户组件文件路径

5. **按步骤应用样式修改**
   a. 先确认修改策略
    - 如果当前是父组件，且子组件已有独立的 Figma 映射 → 按映射分别修改
    - 如果子组件没有独立映射但有父组件设计稿 → 尝试从父组件设计上下文中提取对应子组件的样式信息
   b. 根据[design_context]中的信息
     - **Tailwind**: 更新 className 中的工具类
     - **CSS Modules**: 修改 .module.css 中的样式规则
     - **Styled-components**: 更新样式模板字符串
     - **CSS-in-JS**: 修改样式对象
   - **约束**：
     - 保持组件结构和交互逻辑不变，仅修改视觉样式
     - **绝对不能删除所引用的组件**
     - 修改子组件样式时需先找到子组件文件再修改

6. **验证修改**
   - 检查修改后的代码语法是否正确
   - 如有 TypeScript 类型错误，尝试自动修复或提示用户
   - 询问用户是否需要预览修改效果

7. **询问额外修改需求**
   - 完成所有组件的样式修改后，必须询问用户：
     > "是否还有其他需要修改的样式或组件？如果有，请提供组件名到 Figma node 的映射表。"
   - 如果用户提供了新的映射表，返回步骤 1 继续处理
   - 如果用户没有额外需求，进入步骤 7

8. **生成修改报告**
   - 记录每个组件的修改内容：
     - 修改的文件路径
     - 样式变更摘要（颜色、字体、间距等）
     - 修改前后的对比

## 工具使用

- **Figma MCP**:
  - `get_design_context` - 获取组件设计信息
  - `get_variable_defs` - 获取设计 token/变量
  - `get_screenshot` - 获取组件截图用于对比

- **代码修改**:
  - 使用 `Read` 和 `Edit` 工具修改代码文件
  - 使用 `Grep` 搜索组件文件

## 输入

- 组件名到 Figma node 的映射表
- 项目中的组件代码文件

## 输出

- 修改后的组件代码文件
- 修改报告，包含：
  - 处理的组件列表
  - 每个组件的样式变更详情
  - 修改的文件路径

## 注意事项

- 修改前建议用户先提交当前代码，以便必要时回滚
- 如果 Figma 设计稿使用了设计 token，尝试映射到项目中的对应 token
- 对于复杂的样式（如渐变、动画），可能需要人工介入
- 保持组件的可访问性（Accessibility）属性不变

**约束规则**
1. 功能完整性优先
  - 不能删除任何原有的业务逻辑、状态变量、导入
  - 不能删除组件引用
  - 保持所有 props、state、事件处理函数不变
  - **如果组件中有引用其他组件则修改引用组件的样式，绝对不能删除所引用的组件**

2. 样式与逻辑分离
  - 只修改 className、style、布局结构
  - 不触碰 useState、useEffect、事件处理等逻辑代码
  - 不删除导入，保留所有原有的组件引用

3. 检查清单
修改前先确认：
  - 有没有删除导入？
  - 有没有删除 state？
  - 有没有删除事件处理函数？
  - 有没有改变组件的 props 接口？
