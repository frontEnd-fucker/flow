## 概述
根据requirements阶段的的设计文档（位置：`docs/[requirements].md`）编写全面的实现计划，将整个计划拆解为多个可独立开发，独立测试的任务。

## 约束规则（必须遵守）
- 对于通用逻辑，如通用utils, components, hook必须采用TDD开发模式，先写测试用例再写代码
- 使用 `- [ ] Step N` 格式标记每个子任务

## 任务结构
```
### 任务 N：[任务名称]

- [ ] **步骤 1: 编写测试用例（如适用）**
- [ ] **步骤 2: 运行测试用例验证它失败(如适用)**
- [ ] **步骤 3：实现逻辑**
- [ ] **步骤 4: 运行测试用例直到它通过，不通过则回到步骤3**
- [ ] **步骤 5：标记任务完成**
- [ ] **步骤 6: 提交代码**
```


## 输出：执行计划文档（docs/[计划名称]-plan.md）

完成此阶段后，输出执行计划，文件保存到 docs/[计划名称]-plan.md：

```
## 执行计划

### 任务清单

[ ] task 1: [任务描述]
    - 文件: [涉及的文件]
    - 依赖: [前置依赖]
    - 验收标准: [如何验证完成]

[ ] task 2: [任务描述]
    ...

### 目录结构

```
src/
├── components/
├── services/
└── ...
```

### 风险与依赖

- 外部依赖: [如 npm 包、API]
- 内部依赖: [各任务间的依赖关系]
- 已知风险: [可能的问题及应对方案]
```

### 完成后

- 向用户展示执行计划
- 等待用户 Review & Approve
- 获得批准后才能进入coding阶段 ../coding/skill.md` 
- 如有修改要求，调整计划后再次提交批准
