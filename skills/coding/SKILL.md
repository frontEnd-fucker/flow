## 核心开发

这是 AI 协作开发工作流的coding阶段。遵循标准化开发流程，确保代码质量和可维护性。

### 开发执行流

#### 前置准备：读取执行计划文档

从 planning 阶段输出的执行计划文档（`docs/*-plan.md`）中获取：
- 任务清单（Task List）
- 每个任务的依赖关系
- 验收标准
- 目录结构设计

开发必须严格按照执行计划中的任务顺序和依赖关系进行。


#### 多 Agent 并行开发

**每个独立任务必须分配一个独立的 subagent 进行开发。**

**使用 `Agent` 工具分配任务：**
```json
{
  "description": "[任务名称（简短描述）]",
  "prompt": "[详细任务描述...]",
  "subagent_type": "general-purpose"
}
```

**分配规则：**
1. **任务独立性判断** - 检查任务清单中的任务是否有依赖关系
2. **无依赖任务并行** - 可以同时启动多个 subagent 处理独立任务
3. **有依赖任务串行** - 依赖前置任务完成后，才能启动后续 subagent
4. **每个 subagent 专注一个任务** - 禁止在一个 subagent 中处理多个任务

**模块类型判断与开发模式选择：**

在分配任务前，先判断任务类型，决定是否需要 TDD：

| 模块类型 | 特征 | 开发模式 | 示例 |
|---------|------|---------|------|
| **通用模块** | 可复用、无业务逻辑、被多处引用 | **必须 TDD** | `utils/`, `hooks/`, `components/` 中的通用组件 |
| **业务模块** | 特定页面/功能、包含业务逻辑 | **跳过 TDD** | `pages/`, `features/`, `services/` 中的业务代码 |

**判断标准：**
- 如果模块会被多个页面/功能引用 → **通用模块，必须 TDD**
- 如果模块只服务于特定业务功能 → **业务模块，跳过 TDD**
- 如果无法确定，默认按业务模块处理

**Subagent Prompt 模板：**
```
你是 AI 开发助手，负责完成以下任务：

任务：[复制任务内容]
模块类型：[通用模块/业务模块]
依赖任务：[依赖的任务内容]

开发模式：
[如果是通用模块]
1. **必须遵循 TDD 开发流程**（先写测试，再写实现）
2. 确保测试覆盖所有边界情况
3. 实现后运行测试确保通过

[如果是业务模块]
1. **跳过 TDD 流程**，直接实现功能
2. 关注功能完整性和用户体验
3. 如需调试，可使用 Chrome DevTool MCP

通用要求：
1. 使用原子化提交（每个逻辑步骤单独提交）
2. 完成后报告：完成的功能、文件变更、测试覆盖情况（如适用）

开始工作前，先检查是否有前置依赖需要等待。
```

**协调与汇总：**
- 主 agent 负责监控所有 subagent 的执行状态
- 所有 subagent 完成后，汇总结果并向用户报告整体完成情况
- 如有子任务失败，记录错误并决定是否需要重试或调整计划

#### 原子化提交

严格遵循任务清单执行：

- 每个子任务单独提交
- 提交信息清晰描述改动
- 可以使用多 agent 并行处理独立任务

提交规范：
```
feat: 添加用户认证功能

- 实现 JWT 登录
- 添加 token 刷新逻辑
- 集成用户权限检查
```

#### 环境协作

**Git Worktree 隔离**:
- 使用 `git worktree` 创建独立的开发分支
- 避免污染主分支
- 方便并行多个任务


### 执行流程

1. 从任务清单中选择当前任务
2. 使用 TDD 方式开发：
   - 先写单元测试
   - 编写实现
   - 运行单元测试
3. 原子化提交
4. 继续下一个任务

### 完成后

- 向用户宣告： "所有开发任务已完成。进入自动化浏览器验证阶段"
- 调用 `../auto-browser/skill.md` 进入自动化浏览器验证阶段

### 关键原则

1. **通用逻辑永远先写测试**: 通用逻辑不要跳过 TDD 流程
2. **项目初始化在当前目录下**: 将项目初始化在当前目录下
3. **不要删除任何文档和原型文件**: 不要删除 `docs` 文件夹和 `prototype` 文件夹下的任何文件
4. **注释**: 每个文件的开头需要注释说明该文件的作用
5. **保持提交原子性**: 一个提交只做一件事
6. **使用 worktree**: 保护主分支的清洁
