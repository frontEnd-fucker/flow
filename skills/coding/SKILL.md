## 核心开发规则
通过为每个任务分发新的子代理来执行计划.

### 开发执行流

#### 前置准备：读取执行计划文档

从 planning 阶段输出的执行计划文档（`docs/*-plan.md`）中获取：
- 任务清单（Task List）
- 每个任务的依赖关系
- 验收标准
- 目录结构设计

开发必须严格按照执行计划中的任务顺序和依赖关系进行。

#### 多 Agent 并行开发

**每个独立任务必须分配一个独立的implementer subagent(./coding-standards.md) 进行开发。**
**在分发前，必须先读取 ./coding-standards.md，并将其内容作为 subagent 的 prompt 模板**

**分配规则：**
1. **任务独立性判断** - 检查任务清单中的任务是否有依赖关系
2. **无依赖任务并行** - 可以同时启动多个 subagent 处理独立任务
3. **有依赖任务串行** - 依赖前置任务完成后，才能启动后续 subagent
4. **每个 subagent 专注一个任务** - 禁止在一个 subagent 中处理多个任务

------

**协调与汇总：**
- 主 agent 负责监控所有 subagent 的执行状态
- 当完成一个任务时，在执行计划文档（`docs/*-plan.md`）的对应任务打上勾 `-[x]`
- 所有 subagent 完成后，汇总结果并向用户报告整体完成情况
- 如有子任务失败，记录错误并决定是否需要重试或调整计划

### 完成后
- 检查是否已完成所有任务，确保所有任务已完成
- 向用户宣告： "所有开发任务已完成。进入自动化浏览器验证阶段"
- 调用auto-browser skill(`../auto-browser/skill.md`) 进入自动化浏览器验证阶段

### 关键原则
1. **任务完整性**: 不要跳过任务
2. **通用逻辑永远先写测试**: 通用逻辑不要跳过 TDD 流程
3. **项目初始化在当前目录下**: 将项目初始化在当前目录下
4. **不要删除任何文档和原型文件**: 不要删除 `docs` 文件夹和 `prototype` 文件夹下的任何文件
