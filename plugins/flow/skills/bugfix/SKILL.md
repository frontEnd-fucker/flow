## Step 5: 缺陷工单处理

这是 AI 协作开发工作流的第五个阶段。用于处理线上问题或已知缺陷。

### 关键任务

#### 1. 工单分析

理解并明确问题：

- **复现步骤**: 明确如何复现问题
- **期望行为**: 描述正确的行为是什么
- **实际行为**: 描述当前观察到的错误行为
- **环境信息**: 浏览器、设备、操作系统等

#### 2. 单一假设 (Single Hypothesis)

**核心原则**: 每次只验证一个变量

- 明确陈述假设："我认为 X 是原因，因为 Y"
- 不要同时测试多个假设
- 记录每个假设及其验证结果

假设格式：
```
假设 #1: [具体假设]
- 理由: [为什么认为是这个原因]
- 验证方法: [如何验证]
- 结果: [通过/失败]
```

#### 3. 最小化测试

- 做出**最小**的改动来验证假设
- 不要做看似相关但未经证实的修改
- 每次修改后立即验证

### 调试流程

1. **分析工单**
   - 收集所有相关信息
   - 尝试复现问题
   - 制定初始假设

2. **验证假设**
   - 做最小改动
   - 运行测试验证
   - 记录结果

3. **如失败**
   - **必须撤销改动**
   - 形成新假设
   - 回到步骤 2

4. **如成功**
   - 确认修复完整
   - 添加测试用例防止回归
   - 提交修复

### 输出：缺陷分析报告

```
## 缺陷分析报告

### 问题描述
- 标题: [问题标题]
- 严重程度: [P0/P1/P2/P3]
- 影响范围: [用户百分比/功能模块]

### 复现步骤
1. [步骤1]
2. [步骤2]
3. [步骤3]

### 假设验证
假设 #1: [原因描述]
- 验证方法: [具体操作]
- 结果: ❌ 失败

假设 #2: [原因描述]
- 验证方法: [具体操作]
- 结果: ✅ 成功

### 修复内容
[具体修改的代码]

### 测试用例
[添加的测试用例]
```

### 关键原则

1. **单一假设**: 每次只验证一个变量
2. **最小改动**: 只做验证假设所需的最小修改
3. **必须撤销**: 失败的假设必须撤销改动
4. **新假设**: 失败后形成新的假设继续验证
5. **测试保护**: 修复后添加测试防止回归

### 完成后
- 在浏览器中验证
- 向用户展示缺陷分析报告
- 确认修复方案
- 完成任务
