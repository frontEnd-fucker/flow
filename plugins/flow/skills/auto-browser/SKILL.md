# Auto Browser

根据项目验收标准自动进行浏览器验证，发现问题后分析根因、最小化修复并复验。

## 开始

1. 读取 `docs/requirements.md`，提取验收标准。
2. 按页面分组解析：
   - 标题中包含 `【页面】` 的行是页面标题，支持任意 Markdown 标题层级。
   - 页面标题下的每个 `- [ ]` 列表项是一条验收项。
   - 若没有 `【页面】` 分组，则使用文档中的验收标准标题或 `未分组` 作为页面名。
3. 如果没有找到验收项，询问用户提供验收清单或指定文档路径。

## 选择验收项

按以下优先级决定要验证的验收项：

1. 用户已经明确指定页面、编号或验收项文本时，只验证指定项。
2. 用户说“全部”“所有”或 `all` 时，验证全部解析出的验收项。
3. 用户没有指定范围且验收项数量不多时，默认验证全部，并先简短列出即将验证的内容。
4. 用户没有指定范围且验收项很多时，先按页面输出编号列表，请用户用纯文本回复编号，例如 `1,3,5-7`。

运行时交互规则：

- Claude Code 中，如果当前环境支持 `AskUserQuestion` 或交互式多选工具，可以用它让用户选择验收项。
- Codex 中，不要假设存在 Claude Code 的交互式选择工具或可点击选项按钮；使用编号文本选择或默认验证全部。
- 任意环境中，如果多选 UI 不可用，不要把这当作阻塞问题，直接使用编号文本选择或默认全部验证。

选择后向用户确认本轮验证范围，格式如下：

```text
我将验证以下验收标准：

【登录页】
- 用户可以通过邮箱和密码登录
- 密码错误时显示提示信息

【首页】
- 展示用户统计数据
```

## 浏览器验证

1. 优先使用当前运行环境可用的浏览器自动化能力。
2. 在 Codex 中：
   - 对 localhost、127.0.0.1、file:// 等本地目标，优先使用 Browser 插件或内置浏览器。
   - 只有当任务依赖用户 Chrome 登录态、Cookie、扩展或已有标签页时，才使用 Chrome。
3. 在 Claude Code 中，使用已配置的浏览器自动化 MCP 或工具。
4. 对每条选中的验收项执行验证，记录通过、失败、证据和复现路径。
5. 若发现失败：
   - 先说明最可能根因。
   - 做最小合理修改。
   - 修改后重新运行相关验收项。

## 完成

1. 仅汇总已验证的验收项，按页面分组展示结果。
2. 对失败后已修复的项目，说明修复点和复验结果。
3. 完成后进入代码评审流程：
   - Claude Code 中可调用 `/flow:code-review`。
   - Codex 中使用 `flow` 的 `code-review` skill 或当前环境可用的代码评审流程。
